# iPhone workspace audit and implementation plan

**Date:** November 16, 2026 · **Scope:** the Home Screen web app, not a native iOS binary.

## Findings

| Priority | Observed | Planned correction |
| --- | --- | --- |
| P0 | The supplied iPhone image shows the top controls crossing the record header. The mobile toolbar adds safe-area padding inside a fixed 56 px height. | Give the chrome its own content height plus insets; reserve room above the home indicator and below the final interactive row. |
| P0 | Desktop columns and sticky cells compete for width. The stone name breaks inside words and sits inline with its ID. | Reflow shared tables into labeled records; give stock a full-width identity row, separate specification, and an explicit details affordance. Keep desktop tables. |
| P1 | Alerts, theme, account and search compete with the section title. Search appears global but only filters inventory. | Use a compact toolbar, honest stock-search scope, relevant destinations, and a grouped More sheet. Keep five or fewer role-aware destinations. |
| P1 | Receive stock is duplicated on mobile; filters can start offscreen; the fixed selection bar can cover other records. | Keep one primary receive action, anchor Filters beside the view switch and keep selection actions in the record flow. |
| P1 | A grab-shaped widget is a small close target, not an actual drag control. Several sheets and controls retain desktop sizing. | Use native modal focus and a labeled close button, 44 px touch controls, 16 px form inputs, and short reduced-motion-aware sheet entry. Preserve native scrolling. |
| P1 | Home Screen metadata is partial; assistant and extraction surfaces need a clear distinction between source, generated text, and verified fields. | Ship an icon and standalone manifest. Keep AI optional/read-only, explicitly label generated output, and preserve required human confirmation. |

## Research and design constraints

- [Apple HIG: Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars): stable, labeled primary destinations. [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility): size and space controls for touch. [Motion](https://developer.apple.com/design/human-interface-guidelines/motion): meaningful, optional motion.
- [WebKit: Home Screen web apps](https://webkit.org/blog/13878/) and [Safari 26](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/): use standalone metadata and respect WebKit's viewport behavior rather than drawing fake system chrome.
- Applied the installed Apple Design, Mobile Native, Antislop UI/mobile/human/copy and animation-performance guidance: system typography, one accent, grouped surfaces with a job, role-specific copy, and no scroll hijacking, decorative entrance cascades, or invented data.

## Execution and verification plan

1. Rework shared chrome, tabs, sheets and safe-area sizing.
2. Reflow Overview, Inventory, business records and the AI workspace without changing data access, accounting or evidence approval.
3. Add branded Home Screen assets without extending offline access to private records.
4. Build, lint, run API tests and exercise touch layouts, detail dialogs, filters, More, dark mode, the AI states and narrow widths using isolated browser data. Check iOS Simulator when available. Record what still needs a physical iPhone.

## Verification and handoff

- Build, TypeScript, lint and all 19 API tests passed. Browser and API tests now start from an empty temporary SQLite file so demo and workstation records cannot leak into assertions.
- WebKit: 6 passing tests (three end-to-end workspace journeys and three mobile tests). Chromium: 3 passing mobile tests. The mobile checks cover 320 px route reflow, safe-area geometry at 402 px, touch targets, list/card modes, keyboard focus return, reduced motion and scroll-to-top, role tabs, dark appearance, Home Screen assets, and AI draft confirmation. The targeted browser runs did not run the standalone provisioned-account role audit.
- Viewed the production build with synthetic gemstone records in Safari on an iPhone 17 simulator running iOS 26.5. The screenshot confirms the toolbar and first records no longer collide or split long stone names. AI responses were simulated; no reports were sent to a live AI provider.
- Before publishing, verify on a physical iPhone from the deployed HTTPS origin: add to Home Screen, cold-launch the icon, rotate, open a sheet using the keyboard, enable VoiceOver and Reduce Motion, and check that the last action remains reachable above the home indicator. No production deployment was performed.
