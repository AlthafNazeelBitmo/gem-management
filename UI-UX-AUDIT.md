# Gem Management — UI/UX audit
**16 November 2026 · Local working checkout · Audit only; no product code changed**

## Verdict

The app has a strong operational foundation: permanent stone IDs, explicit custody, legible state text, native dialogs, and separate buyer-facing disclosures. Keep the restrained typography and motion. **Fix the trust and recovery issues before relying on this interface for live pricing, intake, or selling away from the office.** The biggest gaps are not decorative: the interface can display the wrong currency, invite a duplicate submission, hide controls at widths between phone and desktop, and accept a local sale after a show assignment has been released.

### Release blockers and high-priority defects

| ID | Finding and reproduction | Recommendation and regression check |
|---|---|---|
| **P1-01 · Currency** | **Reproduced with SQLite.** Set up an LKR workspace and receive a stone priced at 2400. Inventory List and Cards say **$2400.00**; the detail says **2400.00** with no currency. The List renderer also feeds desktop Recent stock. The same hard-coded symbol can misstate other currencies. `src/main.tsx:1198–1206,1325–1331,4524–4530`. | Use one formatter taking amount, currency code and configured precision; use an explicit code on business records when a symbol is ambiguous. Keep monetary values as decimal strings. Verify LKR, USD, JPY (0 decimals), a 3-decimal currency, and unpriced zero in List, Cards, detail and buyer views. |
| **P1-02 · Save/retry** | **Reproduced with a real write and a simulated failed read.** In Customers, let the create request succeed, then return HTTP 503 on the following workspace refresh. The editor stays open, shows the refresh error, and re-enables **Save customer**. Pressing it again persisted **two customer records**. The shared command helper awaits the refresh before reporting a successful write, so other command-based dialogs can misreport a committed action too; those individual mutations were not retested. `src/main.tsx:881–898,533–550`. | Distinguish **Saved — could not refresh records** from a rejected write. Close or mark the editor committed; offer **Refresh records**, not another submission. Preserve the returned ID, and add idempotency to high-risk create/post actions where a response can be lost. Regression: success + refresh 503 + retry reading = one record. |
| **P1-03 · Tablet toolbar** | **Reproduced in Chromium with a fine pointer.** The root measures **924 CSS px** at 761, 800 and 900px. At 800px the profile/settings button spans x=797–924; nearly all of it is off-screen, with body horizontal overflow clipped. Reproduced on Overview, Inventory, Purchasing, Quotes, Sales, Payments and Settings. The same 800px view squeezes the first recent-stock name to roughly one letter per line; the local table scroll area does not prevent column collapse. `src/styles.css:57–62,622–654,704–708,2321–2350`. | Let the search group shrink, collapse account identity to a full-size icon at an intermediate breakpoint, adapt the toolbar based on available space rather than input type alone, and give scrolled table identity/action columns usable minimum widths. Assert no page overflow and every toolbar target fully inside the viewport at 761/800/900/1024, including touch + mouse and browser zoom. |
| **P1-04 · Released Show mode still queues sales** | **Reproduced on the built app served by Express with SQLite.** Assign two stones, download authority, reload offline, queue a sale and reconnect. The first event reconciles to one invoice. Release the assignment after reconciliation: its row says **Released**, but **Downloaded device authority** and **Queue offline sale** are still active. A second sale is reported as signed and queued after release. The backend clears the show’s key on release, so the old authority is no longer valid for posting. `src/main.tsx:3700–3721,3734–3756,3805–3905`; `server/index.mjs:957–994,1075–1103`. | On release, invalidate matching local authority immediately and keep already queued events visible with an explicit recovery state. On refresh/reconnect, check status and expiry before allowing new entries. Exclude sold or ineligible stones from the selector. Regression: queue offline → replay once → release → no usable queue action for that assignment, including after reload. |

### Workflow and accessibility issues

| ID | Finding and reproduction | Recommendation and regression check |
|---|---|---|
| **P2-01 · Buyer submissions** | **Reproduced with SQLite.** Double-click **Send decision** on a valid private selection. Both POSTs returned 200 and the selection stored two decisions. Expired/missing links also keep the heading **Opening selection…** after the error appears. `src/main.tsx:5414–5432,5484–5510`; `server/index.mjs:871–897`. | Add a pending/sent state, deduplicate accidental repeats at the server, and provide an explicit **Update decision** path if edits are intended. Give expired links a terminal heading and tell the buyer how to request a new link. Test slow network, double activation, changed decisions, and expiry after opening. |
| **P2-02 · Desktop search** | **Reproduced.** The toolbar promises stones, custody, certificates and customers; on Customers, entering a nonmatching term does not change the customer list. On Inventory the toolbar duplicates the local search. Start on Inventory page 3, then search for a variety with nine matches: the first result seen is **Showing 9 to 9 of 9 stones**, not the first page. `src/main.tsx:1623–1653,1843–1854,2336–2344`. | Ship one honest search: either a scoped Inventory search (and open it via ⌘/Ctrl+K) or a real role-filtered cross-record finder. Reset pagination on query changes, trim input, and announce result counts. Verify page 3 → nine matches opens page 1, and unspecified record types are not promised. |
| **P2-03 · Skip link changes the page** | **Reproduced by keyboard.** Open Quotes, focus **Skip to content**, press Enter: focus moves to `main`, but the hash becomes `#main` and the view becomes Overview. Page routes and the anchor use the same fragment. `src/main.tsx:743–745,1589–1594,1666–1668`. | Focus the current main content without overwriting the route. After intentional view changes, focus the destination heading (or announce the view), while restoring the opener on modal dismissal. Test skip from every non-Overview route and Back/Forward after keyboard navigation. |
| **P2-04 · Role-aware dead ends** | **Reproduced with a realistic clerk fixture.** An Inventory clerk sees an overdue outgoing memo on Overview; activating it sets the URL/title to Memos but the heading stays Overview because that destination is not in the clerk’s access map. Clerk also gets price-sort options when the server omits prices. `src/main.tsx:36–50,1589–1594,2202–2211,2348–2361`; `server/index.mjs:316–325,367–378`. | Render a permitted handoff or read-only alert, not a button leading nowhere. Derive sort choices from visible fields, and derive title/active state from the displayed route. Test each role against populated and inaccessible actions, not just page visibility. |
| **P2-05 · Dark mode contrast and accessible names** | **Reproduced with axe and DOM inspection.** Inactive **Cards** text at 320px/dark is **2.35:1** (#475569 on #0f172a; expected 4.5:1 for this text). Axe also flagged the profile control’s visible content not matching its name across the scanned shell, and desktop **Evidence** with a visible count. The desktop view toggle lacks the selected-state semantics already present on mobile. `src/styles.css:952–973`; `src/main.tsx:1725–1740,1923–1937,2262–2280,2316–2334`. | Use a theme-aware foreground; expose a visible account name that matches the control’s accessible name, treating initials as decorative where redundant, and include meaningful evidence counts without changing the voice command unpredictably. Mirror mobile’s `aria-pressed` on desktop. Retest both themes, populated badges, and Voice Control. See [WCAG contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) and [Apple accessibility guidance](https://developer.apple.com/design/human-interface-guidelines/accessibility). |
| **P2-06 · Cancel and discard** | **Reproduced.** Enter data in **Receive stock**, press Escape, reopen: the draft is gone with no warning. Conversely, selecting a filter in the phone sheet and pressing Escape keeps the new filter; there is no clear “changes apply immediately” cue. The editor supports backdrop dismissal as well. `src/main.tsx:450–482,516–525,4370–4498`. | Preserve drafts or guard closing only when consequential edits are dirty; keep Escape/backdrop fast for read-only sheets. Make filters explicitly live with **Done**, or stage changes behind **Apply** with **Cancel** restoring the snapshot. Test both dismissal paths after input. |

### Apple design recommendations

| Area | What works | What to change |
|---|---|---|
| **Overview · Purpose and hierarchy** | Available stock is prominent; custody and evidence are not hidden behind icons. | Put **Needs attention** above **Recent stock**, or show a compact actionable summary near the lead metric. At 320×740 the first fold is occupied by intake, available stock and recent stock; urgent work is below the list. The bell reports nine items in the audit fixture but the list initially exposes only six stones needing review plus one memo. Add **View all** and link directly to the relevant work queue or memo. The custody chip label and tally touch at desktop width; add a gap and allow wrapping. |
| **Navigation · Familiarity** | Role-aware mobile tabs and named destinations make common tasks quick. | Use **Inventory** or **Stock** consistently; the heading, bottom tab, links and shortcuts use different names. Mobile highlights **Sales** on Quotes/Memos even though tapping it opens Sales rather than the current page. Either group those destinations under a true Sales hub or leave the active indicator with More. In More, move the account block below workspaces or keep it behind the profile trigger; it consumes the first screen before most destinations are visible. |
| **Inventory · Simplicity and flexibility** | Mobile cards retain ID, weight, custody, status, and evidence; record details open from the name. | Make the stock name the single desktop detail action where possible; today it duplicates each **View** button and creates extra Tab stops. Keep one primary **Receive stock** control location, put advanced filters behind a predictable boundary, and use concise labels such as **Variety**, **Custody status**, **Location**, **Evidence**. Expose active filters as removable chips and say **No matches — clear filters** rather than suggesting new intake. |
| **Purchasing and forms · Agency** | Workflow notes distinguish agreed orders, received stock, and supplier-owned goods. | Without a supplier, point **Create purchase order** to **Add supplier** rather than opening a required select with no valid choice. For long sales/intake forms, put actionable server errors at the affected field and keep feedback visible next to the action; the generic editor currently places errors at the bottom. Replace multi-select transaction fields with a searchable checklist showing selected records and count, especially on touch. |
| **Evidence and trust · Responsibility** | Wording approval, original-document allowlisting, and read-only AI are strong patterns. | Replace **Approved (Verified)** with **Disclosure approved** where it refers to sign-off, not gem authentication. Approval permits reviewer wording based on supporting claims; it does not imply the gem was independently verified. Keep the AI answer warning and make report extraction’s separate draft/review state explicit. |
| **Visual system · Craft** | Platform type, labeled statuses, quiet hover/press feedback, and reduced-motion support suit this tool. Phone toolbar controls measured 44×44 and tabs 48px high at 390px. | Reconcile the current violet/blue-gray tokens and GemVault/Gem Management naming with the documented Bitmo indigo/bone direction. Keep glass limited to functional layers. Favor larger secondary labels and relative type sizing over more styling, and verify text enlargement and increased contrast on-device. No added motion is necessary. |

| **AI and integrations** | Existing fixture tests covered not configured, answer and extraction review/confirmation. No live AI, Neon, or external integration calls were used. Production hosting, real networks and payment providers were not audited. |

**Quality gate:** Vite production bundle and TypeScript check passed. API/domain suite: **19 passed**. Repository Playwright suite: **8 passed, 12 failed**. All 12 failures are in the existing all-roles spec: its partial Password selector matches both the field and Show password, and the suite assumes accounts not provisioned by its empty database config. Exact locators and disposable users were used in the separate smoke above. The repository role spec also skips absent controls (including destinations behind mobile More); replace this with explicit assertions and create accounts as part of the isolated fixture. ESLint reports two existing `no-explicit-any` errors in `src/api.ts:49,60`; no audit change touched those lines.

## Fix order and acceptance

1. **Before live use:** Fix currency labels, split save from refresh outcomes, and restore usable toolbar controls across widths, and disable released show authority. Retest the end-to-end flows with populated inventory and non-USD settings.
2. **Next UX pass:** Repair buyer submission state, desktop search and pagination, skip-link/route behavior, role-specific dead ends, contrast, and predictable dismissal. Add the exact reproductions above to the browser suite.
3. **Then refine:** Put urgent work first, simplify Stock and More, align terminology, and retest on iPhone Safari/Home Screen, iPad with a trackpad, and macOS VoiceOver/Voice Control. Preserve the app’s density and native controls instead of adding decorative motion.

## Remediation update

The findings and screenshots above describe the pre-fix checkout. The remediation adds explicit stock/buyer currency and precision, separates confirmed writes from refresh failures, adds transactional command receipts for identical retries, keeps the tablet toolbar visible, and revokes stale local Show authority without discarding pending events. The interface now puts urgent work before recent stock, scopes search to Inventory, offers removable filters, guards unsaved form dismissal, associates common validation errors with the relevant fields, and prevents accidental repeat buyer submissions. The role suite now provisions its own SQLite fixture and exercises actual desktop and mobile navigation.

Regression coverage includes four currencies, committed saves with a failed refresh, identical-write retry, 761–1024px desktop layouts, keyboard skipping, populated dark-mode axe checks, filter dismissal, buyer expiry, and remote Show release recovery. A production bundle served by Express also passed cold offline start → signed queue → single invoice on replay → release → no queue action after reload. A device that is already offline cannot learn about a remote release until reconnecting; the server remains the final authority for posting. Native iPhone Home Screen, iPad trackpad, and VoiceOver/Voice Control still need device testing.
